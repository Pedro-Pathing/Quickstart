1Read this first

Almost none of this robot's behavior is hard-coded in Java. It comes from one YAML file. Making the robot work takes three steps: install the app, run the calibration OpModes on the real robot (each one prints numbers), and paste those numbers into the config. Then you verify.

✓
The golden rules
  1. Never edit config.java or config-schema.json. Both are generated.
  2. Numbers go in config.yaml, descriptions and limits in config-docs.yaml. Then run ./gradlew verifyBuild.
  3. Write poses for RED only. BLUE is the letter m (RED rotated 180° about the field centre). Try it on the field map.
  4. Never bypass Sentinel or Casablanca. They keep the robot off the HIVE frame (G417).
  5. Test slowly. Anything that spins goes on blocks first.

4Getting code onto the robot

1 · One-time setup

  1. Install Android Studio and JDK 21 (the build targets Java 21).
  2. Open the repo root (the folder containing gradlew). The robot code is the TeamCode module.
  3. Make sure adb exists: $ANDROID_HOME, $ANDROID_SDK_ROOT or ~/Library/Android/sdk/platform-tools.
  4. Proofs (optional): brew install elan-init. The first verifyBuild then downloads OpenJML and about 5 GB of Mathlib once.
  5. This page: pip install pyyaml, then python3 doc/guide/build.py.

2 · Connect to the Control Hub

Join the robot's Wi-Fi. The hub is at 192.168.43.1:5555.

./gradlew connectAdb
adb devices

USB: use an A-to-C cable. A C-to-C cable from a MacBook didn't work because the hub took the host role. "No route to host" on macOS: allow your terminal under System Settings › Privacy & Security › Local Network.

3 · Verify, then install

./gradlew verifyBuild

This formats, compiles, runs every unit test, checks alliance symmetry and runs the proofs (details). Then in Android Studio pick TeamCode, choose the hub, and press ▶ Run. From the command line:

./gradlew :TeamCode:installDebug

Gradle silent for over a minute? The daemon is frozen. Add --no-daemon.

4 · The tuning loop (no rebuild)

edit config.yaml→pushConfig→stop + re-INIT→test→lock in
./gradlew pushConfig

First it runs checkPushConfig (route safety, ConfigSanity, match windows, under ½ s), then copies the file to /sdcard/FIRST/teamcode/config.yaml. It is ignored unless meta.season = "biobuzz". A plain adb push skips the check, and the robot never re-checks routes itself.

./gradlew resetConfigback to the bundled config

Lock in before competition: final values in the repo, verifyBuild, reinstall, resetConfig.

Getting calibration files off the robot

Calibration OpModes write to /sdcard/FIRST/teamcode/, and each file is overwritten on the next run. Pull it first.

adb pull /sdcard/FIRST/teamcode/shot_table_pollen.yaml calibration-data/
adb pull /sdcard/FIRST/teamcode/shot_time_table.yaml   calibration-data/
adb pull /sdcard/FIRST/teamcode/shot_timing_log.csv    calibration-data/
adb pull /sdcard/FIRST/teamcode/shooter_characterization.json calibration-data/

6Tuning procedures

One card per OpMode. Steps can be ticked off as you go. Controls lights up the gamepad. Writes shows the keys it sets, with their current values. Every calibration OpMode reloads config at INIT, so after each pushConfig, stop and re-INIT.

!
Before every session: charged battery (note its voltage), robot on blocks for anything that spins, clear floor, and a second person on the power switch. Many tuners expose live-editable fields in the Panels dashboard (bylazar Panels).
